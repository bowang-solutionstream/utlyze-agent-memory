# GitHub platform references

Checked 2026-11-03. These describe GitHub behavior; mandatory maximum-five batching is the user’s workflow choice.

- [Creating a pull request](https://docs.github.com/en/pull-requests/how-tos/create-pull-requests/creating-a-pull-request): a PR proposes repository changes between source and target branches; the selected base is where changes will merge.
- [Linking a pull request to an issue](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue): PRs can reference multiple issues; closing keywords targeting the default branch can close linked issues when merged. Use closing behavior only when the issue’s completion criteria are actually satisfied.
- [About Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects): user/organization Projects organize issues and PRs with shared views and metadata. This is a coordination view, not the destination for a code merge.

No live account, repository, permissions, branch protection, remote issue or PR setup was verified or changed by this documentation check.
